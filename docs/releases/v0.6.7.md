## Highlights

- **One set of tools for every agent.** Declare an MCP server once and Claude Code, Codex, OpenCode and Antigravity all get it in every session. A run that falls back to another agent keeps its tools.
  - Where to declare it: `~/.config/agentux/tools.yaml`, `/etc/agentux/tools.yaml` for the whole machine, or `tools` in a project's `agentux.yaml`.
  - Servers can run locally (`command`) or be reached over HTTP (`url`). Their keys and tokens are kept as references to the secret service or systemd credentials, never written in the file.
  - `aux tools` lists what each agent gets. `aux tools add`, `remove` and `test` manage the list; `test` starts a server and shows its tools.
- **Run agents in a sandbox.** `isolation: { agents: { mode: bubblewrap } }` in a project's `agentux.yaml` runs its agents in a Bubblewrap sandbox. An agent there sees:
  - only the run's worktree and the repository (its hooks and config read-only);
  - its own login, and only its own;
  - none of your other files, SSH keys, keyrings, other agents' logins, or services on this machine's `localhost`.

  Git commits inside use your name and email, unsigned; signing and pushing happen outside. The machine or the user can let sandboxes read more paths (`~/.config/agentux/sandbox.yaml`); a project can't, and credential locations are always refused. The sandbox still reaches the network outward, so for now it's meant for workstations (ADRs 0023 and 0024).
- **Signed AgentUX packages.** The agentux, agentux-cockpit and agentux-office RPMs are now signed with the AgentUX RPM key (fingerprint `7217 759E 0D14 1913 9B7C  148C 3116 C5F0 DECE 4517`). The image build refuses any AgentUX RPM without a valid signature, and installed systems carry the key in `/etc/pki/rpm-gpg/RPM-GPG-KEY-agentux`.
- **AgentUX 0.5.2, the cockpit 0.5.13, AgentUX Office 0.1.0.**
- **No new ISO needed.** Installed systems get this release with `sudo bootc upgrade` (or from the software center), then a reboot.
