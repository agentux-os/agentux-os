## Highlights

- **Choose what the machine is for, first.** The Welcome wizard now starts with the profile — Workstation, Agent Node, Command Server, Executive, Complete or Custom — and explains each one: what it does, who it is for, what runs on the machine and how it works with the others. The steps that follow depend on it; installing and signing in to agent CLIs comes after.
- **Manage many machines from AgentUX Command.** A machine can join a Command server: it reports its agents, usage limits, runs and approvals, and takes commands — start or cancel a run, answer an approval, test an agent, lift a limit, change agent preferences. The machine dials out, so no open port or SSH is needed.
- **The machine stays in charge.** `/etc/agentux/node-policy.yaml` sets, per command, whether it runs, waits for someone at the machine to accept it, or is refused. By default, starting runs and changing preferences wait. The cockpit's **Remote control** (in Settings) shows the connection and the commands waiting, with **Accept** and **Reject**; `aux node pending`, `confirm` and `reject` do the same.
- **Join with a token, and only the right server.** Command issues single-use, expiring enrollment tokens. Each token names its Command server, and a machine only ever talks to the server that enrolled it, so two Command servers in one organization never take each other's machines. Paste the token in the wizard, or run `aux node enroll`.
- **Machines that set themselves up.** `aux provision` and the new `agentux-provision.service` configure a machine on first boot from a provision file — profile, host name, Command enrollment, node policy, agent preferences — given through QEMU's fw_cfg, a disk labelled `AGENTUX`, the kernel command line or `/etc`. Command can hand out a ready file with each token, so a fleet of VMs comes up enrolled.
- **API keys from systemd credentials** as well as the desktop's secret service, for machines without a desktop. `aux preferences` reads and changes agent preferences from a terminal.
- **The Command Server profile reads its configuration from `/var/lib/agentux/command/command.env`**, the file AgentUX Command's services use.
- **Updates download in the background, and never restart the machine.** `agentux-update.timer` stages the next image (`bootc upgrade` without `--apply`), skipping metered connections and low battery. The cockpit says when an update is ready and restarts only when you choose.
- **The Welcome wizard finishes what it starts.** It resumes where it was after a reboot, and the cockpit opens only once the wizard is done.
- **What agents may do without asking, per project.** A `permissions` section in `agentux.yaml` allows, asks or denies each kind of tool call (read, edit, run commands, fetch, …), with rules per role: say, the reviewer may never edit. A project's `deny` holds even when the machine approves everything, and every automatic decision is in the run's log (ADR 0021).
- **Agents cannot talk to each other forever.** Each run has a budget for what its agents send each other on the agent bus (`bus.max_tokens_per_run`). Past it, they decide or ask you.
- **Runs started from AgentUX Command know their mission.** A run a Command server starts keeps its organization, mission and definition version, and reports them with every event, so Office follows the work from the mission to the machine. The command connection keeps listening while a long command runs.
- **COSMIC 1.11** for the cockpit's COSMIC integration, and a stricter content security policy in the cockpit.
- **AgentUX 0.5.0, the cockpit 0.5.11.** AgentUX Command 0.2.0 (organization definitions with review, missions as workflows, durable events, an audit trail, backups and restore) is published alongside, for the Command Server profile.
- **No new ISO needed.** Installed systems get this release with `sudo bootc upgrade` (or from the software center), then a reboot.
